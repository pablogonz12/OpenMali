## Findings (experiments; none changed the driver)
- drawcalls: MALI_PROF: per frame cpu: submit waits 3.1-3.5 ms (waiting for the oldest in-flight frame = GPU bound), cmd_submit (CS build) 1.4-1.6 ms for 1000 draws, signal+import 0.07, hw submit_cs 0.2 ms. CS build is ~1.4 us/draw: not the bottleneck. Draw cost on GPU = 5.4 - 2.2 floor = ~3.2 ms, same as the bridge total (2.9-3.5).
- The GPU floor is per-pixel, not per-frame: cube gpu_ms 0.87 at 320x180, 2.13 at 1280x720, 2.31 for drawcalls:1 at 720p. i.e. ~1.3 ms scales with pixel count (linear render target + linear depth, no AFBC; bridge 0.4). Remaining fixed part ~0.75 ms.
- MALI_HF=0 MALI_NOTF=1 (no head/tail flush) saves 0.35 ms gpu_ms on cube (2.61 -> 2.24) but is not validated: not applied.
- ZS Clean Tile Write off when depth is not stored (libkbase fb.c): no gain (2.5 vs 2.6), reverted.
- GPU clock: /sys/class/devfreq/13000000.mali/cur_freq is permission denied for the shell: could not compare clocks (ours vs bridge).
- Validation on CMF with the committed build: t_vk_draw --loop 20, t_vk_compute, t_vk_meta pass (via /tmp/val.sh guest script; qdrv expects libkbase/out binaries).
