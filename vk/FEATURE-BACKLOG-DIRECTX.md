# DirectX backlog: every missing requirement as work packages (2026-11-28)

Source of the gaps: `vk/FEATURE-MATRIX-DIRECTX.md`, generated by `tools/feature-matrix-dx/fmdx.py` from `vulkaninfo --json`
of this tree (main 341853c0, fake v10/v11/v13: these are fake-backend results, not phone results). The real-phone text
captures (x4 v10, cmf v11, 2026-11-28, DroidDeck layers loaded; no v13 capture) never contradict them, but decide only part
of each threshold: d3d11 12_1, dxgi format and vkd3d 12_1 stay UNKNOWN there (no format section in the text), and most other
rows have unknown atoms (matrix section 4). Row ids such as `vkd3d-push-descriptor` are the tool's ids. Upstream commits are in the matrix header.
`vk/check.sh` pins the missing count of every threshold (`FMDX_EXPECT`, next to `DXVK_MISSING`). A package lowers its number
only together with the test that backs the feature (skill pitfall 8).

Status words: PROVEN = from the capture or a cited source line. HYPOTHESIS = hardware claims not yet run on a phone. Effort is in
worker-days. Priority 0-100 means "how close it moves us to a threshold", not how big the package is.

## Threshold 1: "DXVK starts at all" (D3D8, D3D9, D3D10, D3D11)

### WP-1 shaderCullDistance (priority 100, 1-2 d)
- **What:** land PR #350 (`lane/cull-distance`). The VS writes a 0/1 per-vertex varying per cull plane; the FS discards when all
  three vertices are 0, which is Asahi's technique (`agx_nir_lower_cull_distance.c`, see `notes/cull-distance.md`). Set
  `maxCullDistances` = 8 with `maxCombinedClipAndCullDistances` = 8 (`mali_physical_device.c:167`). The older shim PRs #164, #203
  and #205 are superseded: close them.
- **Hardware:** Valhall has no per-primitive cull planes on any architecture. PanVK does not advertise this
  (`panvk_vX_physical_device.c:351`), so there is no oracle. The lowering is the same on v10, v11 and v13.
- **Files:** `vk/src/mali_compile.c` (NIR pass), `mali_physical_device.c`.
- **Depends on:** nothing.
- **Unlocks:** one of DXVK's three device-creation blockers; GL 4.5 through zink.
- **Tests:** `dEQP-VK.clipping.user_defined.*cull*`, then `t_vk_draw` cull cases (pixels on a phone). Lower `DXVK_MISSING` by 1.

### WP-2 descriptorIndexing, the meta-feature (priority 98, 2-3 d)
- **What:** set `descriptorIndexing`, which means every sub-feature the Vulkan spec ties to it. The plain-Vulkan lane
  (`vk/FEATURE-MATRIX-VULKAN.md`) owns that spec list. Today we lack:
  - `shaderUniformTexelBufferArrayDynamicIndexing` and `shaderStorageTexelBufferArrayDynamicIndexing`
  - the `NonUniformIndexing` bits for storage buffers, storage images and texel buffers
  - update-after-bind for storage images, storage buffers and texel buffers
  - limits: `maxPerStageDescriptorUpdateAfterBindStorageBuffers` and `...StorageImages` are 4 today. The spec minimum when
    descriptor indexing is on is 500,000 (HYPOTHESIS from memory; check the spec's required-limits table).
- **Already in flight:** stacked PRs #176, #177 and #188 (`lane/descidx2..4`), #366 (partially bound selects the null
  descriptor), #166 (shim, to close), and `notes/descriptor-indexing.md`. Merge them as one stack onto main and re-bless the goldens.
- **Hardware:** descriptor tables are plain memory on all three architectures, so indexing and update-after-bind are possible.
  PanVK advertises all of it on v9+ (`panvk_vX_physical_device.c:396-411`).
- **Files:** `mali_descriptor.c`, `mali_descriptor_lower.c`, `mali_pipeline_layout.c`, `mali_physical_device.c`.
- **Depends on:** nothing. WP-12 extends it for vkd3d-proton.
- **Unlocks:** the second DXVK blocker, and the base of vkd3d-proton's bindless model.
- **Tests:** `dEQP-VK.descriptor_indexing.*`, `dEQP-VK.binding_model.*` on the host (`vk/deqp/host-run.sh`), then the phone
  runner (PR #391). Lower `DXVK_MISSING` by 1, and lower the `vkd3d:device` pin in `FMDX_EXPECT` by the rows it clears
  there (`vkd3d-bindless-*`), in the same commit.

### WP-3 Geometry shaders, part a: Mesa poly GS through our backend (priority 95, 3 d)
- **What:** finish PR #378 (link Mesa `src/poly` GS/tess lowering as an unmodified library) and PR #392 (poly geometry
  programs through our compiler). Design: `notes/gs-design.md` design C. Estimated 11-15 lane-days to an honest advertisement,
  split here into WP-3 to WP-6.
- **Hardware:** Valhall has no GS stage on v10, v11 or v13. Emulation is a compute pre-pass that writes the GS output to a buffer,
  then a normal draw pulls it with `gl_VertexIndex`. That pull is pixel-identical on the X4 (`notes/tess-design.md`). PanVK keeps
  GS off behind drirc.
- **Files:** `vk/src/mali_gs.c`, `mali_gs.h`, `mali_compile.c`, the meson glue for `libpoly`.
- **Depends on:** nothing. Pass-through GS is merged (#355).

### WP-4 Geometry shaders, part b: the draw path (priority 94, 3-4 d)
- **What:** in the command stream, a compute dispatch per GS draw (indirect counts from the pre-pass), the output buffer from
  the arena, and the following indirect draw. Also covers indexed and instanced draws, primitive restart and
  `multiViewport`/layer outputs.
- **Files:** `mali_cmd.c` and `mali_cs_emit.c` (HOT files: ask the orchestrator first), `mali_pipeline.c` (HOT).
- **Per architecture:** the v10 CSF instruction set differs (see `t_v10_cs`); test v10 separately.
- **Depends on:** WP-3. Related: draft PR #394 (per-draw compute in a pre block).

### WP-5 Geometry shaders, part c: streams, invocations, XFB from GS, statistics (priority 80, 3 d)
- **What:** `geometryStreams`, GS instancing, `transformFeedbackStreamsLinesTriangles`, GS-invocation pipeline statistics, and
  XFB written from the GS output buffer. D3D10/11 stream-out from a GS uses this.
- **Depends on:** WP-4 and the XFB emulation (#313 merged; #260 open).

### WP-6 Advertise geometryShader (priority 99 when WP-3, WP-4 and the GS-instancing part of WP-5 are done, 1 d)
- **Gate:** with `geometryShader` the spec requires `maxGeometryShaderInvocations` >= 32, so GS instancing (WP-5) must
  land first.
- **What:** an advertisement gate backed by `dEQP-VK.geometry.basic.*`, `geometry.input.*`, `geometry.emit.*` and
  `geometry.layered.*` passing on the host and on one phone. Then lower `DXVK_MISSING` by 1.
- **Why a separate package:** DXVK emits no GS of its own (`notes/gs-design.md` §1). The bit is needed only at device creation,
  so games without a GS (for example Megabonk) pay nothing. Advertising before WP-4 needs a design decision from the orchestrator
  (skill rule: never advertise `geometryShader` without one).

### WP-7 VK_KHR_pipeline_library, for DXVK 2.7.1 only (priority 70, 0.5 d)
- **What:** expose the extension: accept `VK_PIPELINE_CREATE_LIBRARY_BIT_KHR` and `VkPipelineLibraryCreateInfoKHR`. Without
  graphics pipeline libraries or ray tracing, no library pipeline is ever linked, but 2.7.1 requires the extension
  (`dxvk-2.7.1/src/dxvk/dxvk_device_info.cpp:878`).
- **Files:** the extension table, `mali_pipeline.c` (HOT, small).
- **Unlocks:** launchers that pin DXVK 2.7.1 (`notes/prior-drivers.md`: faster on Mali for D3D9).
- **Tests:** `dEQP-VK.api.info.*` and the matrix count.

## Threshold 2: D3D11 feature level 11_0 (most D3D11 games ask for 11_0)

### WP-8 Tessellation, part a: TCS/TES through poly (priority 90, 4 d)
- **What:** PR #385 (tess T1, experimental, not advertised). TCS runs as compute through `poly_nir_lower_tcs`, and the TES is
  compiled as the VS of the real draw (`poly_nir_lower_tes(nir, to_hw_vs)`). See `notes/tess-design.md`.
- **Hardware:** no tessellator on v10, v11 or v13.
- **Depends on:** WP-3 (one `libpoly` build serves GS and tess).

### WP-9 Tessellation, part b: tessellator kernels and the draw (priority 89, 4-5 d)
- **What:** PR #388 (tessellator kernels plus the compute WLS/barrier proof), then the draw shape: compute tessellator, then
  indirect draw of the generated domain points. Spacing modes, isolines, `patchControlPoints` (also EDS2
  `extendedDynamicState2PatchControlPoints`).
- **Files:** HOT `mali_cmd.c` and `mali_pipeline.c`.
- **Depends on:** WP-8 and WP-4 (same pre-pass plumbing).

### WP-10 Advertise tessellationShader (priority 92 after WP-9, 1-2 d)
- **What:** gate on `dEQP-VK.tessellation.*` (primitive_discard, winding, spacing, invariance) on the host and one phone. Then
  lower the `d3d11:11_0` count to 0. Optional: `shaderTessellationAndGeometryPointSize`.
- **Unlocks:** D3D11 FL 11_0 through DXVK, the shader level (route-decision-2 §C) and GL 4.0 through zink.

### WP-11 D3D11 API-guaranteed counts DXVK assumes without checking (priority 85, 2 d)
- **What:** DXVK binds up to 8 render targets (`dxvk/dxvk_limits.h:8` MaxNumRenderTargets = 8,
  `d3d11_context_state.h:188` D3D11_SIMULTANEOUS_RENDER_TARGET_COUNT) and 64 UAVs per stage (`d3d11_context_state.h:127`
  D3D11_1_UAV_SLOT_COUNT). D3D11.0 needs 8 UAVs in PS/CS.
- **Gap today:** `maxColorAttachments` = 4, and `maxPerStageDescriptorStorageBuffers`/`...StorageImages` = 4.
- **Why it matters:** this is not a device-creation check, so with these values a D3D11 game that uses 5-8 RTs or more than
  4 UAVs gets a pipeline Vulkan rejects (it breaks silently).
- **In flight:** PR #358 (MRT) and PR #389 (8 SSBOs and images per stage).
- **Hardware:** Valhall has 8 colour buffers; PanVK `.maxColorAttachments = max_cbuf_atts` (`:1010`).
- **Files:** `mali_physical_device.c`, the RT/blend descriptors in `mali_cs_emit.c` (HOT).
- **Tests:** `dEQP-VK.renderpass.*.attachment*`, `pipeline.*.multiple_render_targets`, `binding_model.shader_access.*`.

## Threshold 3: vkd3d-proton device creation (D3D12 starts at all)

### WP-12 Descriptor indexing for vkd3d-proton (priority 88, 2 d)
- **What:** on top of WP-2, add `shaderStorageTexelBufferArrayNonUniformIndexing`, `shaderStorageImageArrayNonUniformIndexing`
  and `descriptorBindingVariableDescriptorCount` (`vkd3d-proton/libs/vkd3d/state.c:8294-8301`).
- **Depends on:** WP-2.

### WP-13 Update-after-bind counts of 1,000,000 (priority 87, 2-3 d)
- **What:** raise `maxPerStageDescriptorUpdateAfterBind{SampledImages,StorageImages,StorageBuffers}` to at least 1,000,000
  (`state.c:8151-8156`, `vkd3d_private.h:67`; ours 500,000 / 4 / 4) and the matching `maxDescriptorSetUpdateAfterBind*`.
- **Cost:** pools and set layouts must be able to hold 1M descriptors, which is tens of MB of descriptor memory per heap.
  Check the kbase allocation limits on 4 GB phones.
- **Alternative:** `VK_EXT_descriptor_buffer` (WP-27) removes this check but is a far larger package.
- **Optional extras:** UBO UAB at 1M avoids CBV-as-SSBO (`state.c:7764`). `minStorageBufferOffsetAlignment` <= 16 (ours 256)
  enables the RAW_SSBO path (`state.c:7770`).
- **Files:** `mali_descriptor.c`, `mali_physical_device.c`.

### WP-14 VK_KHR_push_descriptor (priority 86, 1-2 d)
- **What:** refresh PR #43 (`feat/push-descriptor`, last commit 372d4649) onto main.
- **Hardware:** pure driver work on all architectures. PanVK has it.
- **Files:** `mali_descriptor.c`, `mali_cmd.c` (HOT: the bind path).
- **Tests:** `dEQP-VK.pipeline.*.push_descriptor.*`, `dEQP-VK.binding_model.push_descriptor.*`.

### WP-15 robustImageAccess2 (+ robustImageAccess) (priority 85, 2-3 d)
- **What:** out-of-bounds image loads and fetches return 0 (alpha 0 or 1 by format) and OOB stores are dropped. Use
  `nir_lower_robust_access` image clamps (the robust-access flag from #109) plus null image descriptors.
- **In flight:** PR #373 (robustImageAccess measured on the X8).
- **Hardware:** the texture unit clamps coordinates but does not zero them, so this needs shader-side bounds checks; it costs
  ALU on every image op. Advertise only with the lowering on. PanVK does not advertise `robustImageAccess2`.
- **Tests:** `dEQP-VK.robustness.robustness2.*image*`, `robustness.image_robustness.*`.

### WP-16 Transform-feedback queries (priority 84, 1-2 d)
- **What:** set `transformFeedbackQueries`: `VK_QUERY_TYPE_TRANSFORM_FEEDBACK_STREAM_EXT` (primitives written and needed),
  counted by the XFB lowering (#313, on by default) into the query slot. vkd3d-proton refuses without it
  (`device.c:2517-2521`).
- **Files:** `mali_query.c`, `mali_query_core.c`, `mali_tf.h`.
- **Tests:** `dEQP-VK.transform_feedback.simple.query_*`.

### WP-17 Single-texel alignment for texel buffers (priority 84, 1 d)
- **What:** set `storageTexelBufferOffsetSingleTexelAlignment` and `uniformTexelBufferOffsetSingleTexelAlignment`, and lower
  `*TexelBufferOffsetAlignmentBytes`. Ours: 256 and false (`mali_physical_device.c:234`).
- **Hardware:** PanVK advertises 16/true and 4/true (`panvk_vX_physical_device.c:1205-1208`, `.minTexelBufferOffsetAlignment = 16`),
  so the buffer descriptor takes unaligned bases (HYPOTHESIS until a pixel test on a phone).
- **Tests:** `dEQP-VK.texture.buffer.*offset*`.

## Threshold 4: DXIL shaders (vkd3d SM 6.0 and up: practically every D3D12 game)

### WP-18 Subgroup operations in the fragment stage (priority 83, 1-2 d)
- **What:** `subgroupSupportedStages` is compute only (`mali_physical_device.c:209`, "fragment stage only after a pixel test").
  SM 6.0 needs compute + fragment with basic, vote, arithmetic, ballot, shuffle and quad (`device.c:9799-9832`).
- **Hardware:** warps are 16 wide on all three architectures. Quad ops in the FS need helper invocations.
- **Tests:** `dEQP-VK.subgroups.*.framebuffer.*` (fragment) on the host and one phone.

### WP-19 Float controls: denorm flush and preserve (priority 75, 2 d)
- **What:** SM 6.2 needs `denormBehaviorIndependence` != NONE, `shaderDenormFlushToZeroFloat32` and
  `shaderDenormPreserveFloat32` (`device.c:9848-9861`). PanVK advertises all of them (`panvk_vX_physical_device.c:1084-1096`):
  Valhall FMA/ADD have per-instruction denorm modes.
- **Files:** `mali_compile.c` (pass the float-controls execution mode to the Bifrost/Valhall compiler).
- **Tests:** `dEQP-VK.spirv_assembly.instruction.*.float_controls.*`.

### WP-20 SM 6.6: compute derivatives and 64-bit buffer atomics (priority 65, 2-3 d)
- **What:** `computeDerivativeGroupLinear` (VK_KHR_compute_shader_derivatives; PanVK v9+) and `shaderBufferInt64Atomics`
  (PanVK v9+) (`device.c:9912-9917`). UE5 titles need SM 6.6.
- **Tests:** `dEQP-VK.compute.*derivatives*`, `dEQP-VK.atomic_operations.*64*`.

## Higher feature levels (after thresholds 1-4)

### WP-21 vertexPipelineStoresAndAtomics (priority 60, 2-3 d)
- **What:** gates D3D11 FL 11_1 (`d3d11_features.cpp:201`), vkd3d FL 11_1 (`device.c:9708`) and D3D9 software vertex
  processing (`d3d9_device.cpp:4759`). PR #372 explains why it stays false: IDVS may run the VS speculatively or twice.
- **Per architecture:** PanVK enables it only on v13 (drirc, `:337`). Plan: v13 first; on v10/v11 disable IDVS for pipelines
  whose VS stores.
- **Also needs:** for vkd3d FL 11_1, 64 storage buffers and images per stage (WP-11 raised to 64).

### WP-22 Tiled resources tier 2 (sparse) (priority 55, 6-10 d, split into 3 packages)
- **Needs:** `sparseBinding`, `sparseResidencyBuffer`, `sparseResidencyImage2D`, `sparseResidencyAliased`, the standard 2D block
  shape, `shaderResourceResidency`, `shaderResourceMinLod`, `samplerFilterMinmax` and `residencyNonResidentStrict`, plus a
  queue with SPARSE_BINDING (`d3d11_features.cpp:319-347`, vkd3d `device.c:8994-9015`). D3D12 FL 12_0, which many D3D12 games
  require, needs it together with WP-23.
- **Hardware:** PanVK has sparse binding and residency on v10+ but not aliased (panfrost issue 237). kbase GPU VA remapping is
  the mechanism. Residency feedback in shaders (`sparseResidency` codes) is a compiler question (HYPOTHESIS).
- **Packages:** (a) sparse binding queue + buffer; (b) 2D image residency with the standard block shape; (c) aliased residency,
  shader residency and min-LOD, plus `samplerFilterMinmax` (PanVK v10+ `EXT_sampler_filter_minmax`).

### WP-23 Typed UAV loads without format (priority 58, 1-2 d)
- **What:** `shaderStorageImageReadWithoutFormat` (PanVK true) plus STORAGE_IMAGE on the 18 formats (`d3d11_features.cpp:350-388`,
  vkd3d `device.c:9159`). Needed by D3D11 FL 12_0 and D3D12 FL 12_0.
- **Limit of the tool:** STORAGE_READ_WITHOUT_FORMAT is a FormatProperties3 bit that vulkaninfo JSON does not carry, so it is
  checked through a proxy.

### WP-24 Conservative rasterization (v11 and v13 only) and ROV (priority 30, 3+ d)
- **Conservative rasterization:** PanVK v11+ (`:151`). On v10, never advertise it.
- **ROV** (`fragmentShaderPixelInterlock` + `fragmentShaderSampleInterlock`): no known Valhall interface (HYPOTHESIS; PanVK does
  not advertise it). Without ROV, D3D12/D3D11 FL 12_1 stays out of reach.

### WP-25 D3D12 FL 12_2 / DX Ultimate: do not plan
- Needs mesh shaders, ray tracing 1.1, VRS tier 2, sampler feedback and `depthBounds`. None is native on v10/v11.
- The v13 Immortalis class has ray-tracing hardware (HYPOTHESIS for the G925 in the X8), so this is a research item, not a package.
