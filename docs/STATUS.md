## Footer: what each denominator counts as

- **Entry points** 190: the core (non-extension) commands in `vk/tests/dxvk_api_table.h`, the
  app-visible Vulkan 1.3 command set the tests use (generated from vk.xml by `vk/tests/gen_dxvk_api.py`).
  It is not the whole registry: platform WSI and extension entry points are excluded. Numerator: a
  `mali_<Name>` definition (nm on the built ICD, or a source scan without a build); "answered" adds
  the commands whose `vk_common_<Name>` object is linked in, i.e. Mesa's runtime serves them.
- **Extensions** 63: the union of both extension tables in the tree and DXVK 3.x's required
  list (`dxvk_exts` in `vk/tests/t_dxvk_caps.c`). "Partial" means the table's own comment qualifies the
  support ("only", "smoke", …), not a separate test result.
- **Formats** 184: `VK_FORMAT_ASTC_12x12_SRGB_BLOCK`, the last Vulkan 1.3 core format. The
  driver scans `1..156` on purpose; the panel also shows that narrower range.
- **Features** 70: the 55 `VkPhysicalDeviceFeatures` bits plus the 15
  `VkPhysicalDeviceVulkan13Features` bits, listed in `tools/status/features-vk13.txt` (generated from
  vk.xml). 1.1/1.2 and extension feature bits are reported separately, not in the denominator.
- **Tests**: case results from `vk/out/native/check.log`; a case counts once per named run, so the
  v11/v13 loop cases count twice.
- Anything the tree cannot prove is printed as *unknown*, never as 0% or 100%.
