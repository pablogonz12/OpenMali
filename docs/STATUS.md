## Where each number comes from

- Entry points: vk/src/*.c:^mali_<Name>( (or nm on the ICD) vs vk/tests/dxvk_api_table.h core rows. Numerator: `nm` on the built ICD (`mali_*`), plus
  `vk_common_*` objects for the Mesa runtime; without a build the scan is source-only and the
  runtime column reads *unknown*.
- Extensions: vk/src/mali_instance.c:22 instance table, vk/src/mali_physical_device.c:226 device table, vk/tests/t_dxvk_caps.c:33 reference set. `partial` comes from the table's own comment (`only`, `smoke`).
- Formats: `vk/src/mali_format.c` is the table; the per-format answer is the driver's own
  `vkGetPhysicalDeviceFormatProperties` on the fake GPU, so a format listed but probed as zero
  features is reported not done.
- Features: vk/src/mali_physical_device.c:207 feature table, tools/status/features-vk13.txt (55 core 1.0 + 15 core 1.3 bits).
- GPU ladder / pipeline / milestones: `docs/progress.toml` and `ROADMAP.md`, evidence verified here.
- Guest libraries: `docs/libs.toml` `[[lib]]`, hand-edited from dated guest experiments; every evidence
  path/token is verified here, so a row cannot cite a file that does not exist.
- dEQP: committed TSV files under `vk/deqp/`; nothing is re-run by this script.

## Denominator rules

- Entry points 190: core (non-extension) commands in `vk/tests/dxvk_api_table.h`.
- Extensions 64: union of both extension tables and DXVK 3.x's required list.
- Formats 184: the last Vulkan 1.3 core `VkFormat`. The driver's own scan is 1..156, shown too.
- Features 70: 55 core 1.0 + 15 core 1.3 feature bits (`tools/status/features-vk13.txt`), not 1.1/1.2/extension bits.
- Gate cases are not items: they are health checks, so 122/122 does not raise the progress numbers.
- Guest libraries are not items either: works/broken/untested counts the guest surface, not the driver's checklist.
- Partial counts as 0.5 only in the second percentage; the first counts done only.
