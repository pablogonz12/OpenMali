# tools/feature-matrix

`feature_matrix.py` (Python 3, stdlib only) builds `vk/FEATURE-MATRIX-VULKAN.md` and `data/gaps.json` from committed
data, and `vk/check.sh` uses it to fail when the driver stops advertising something the matrix records as present.

| file | what | regenerated by |
|---|---|---|
| `data/refs.json` | extracted reference tables: vk.xml extensions/feature structs/limit types, Vulkan-Profiles requirements, PanVK extension + feature table per arch, zink.rst per-GL requirements, zink_device_info.py extension list, ANGLE extension/feature reads, gamescope list (t_steam_caps.c), Arm blob gpuinfo reports | `extract` |
| `data/ours-v10.json`, `-v11`, `-v13` | our driver, summarised from `vulkaninfo --json` on the fake backend (defaults, no `MALI_EXPERIMENTAL_*`) | `ours` |
| `data/curated.json` | hand facts with sources: hardware limits, env switches, ANGLE ES gates | by hand |
| `data/gaps.json` | every missing extension / feature / limit / format bit with who requires it (citations) | `gen` |

## Regenerate

```sh
# 1. our driver (from vk/, after ./build.sh)
O=$PWD/out/native
for g in v10 v11 v13; do
  env -u MALI_EXPERIMENTAL_MSAA -u MALI_EXPERIMENTAL_TF -u MALI_EXPERIMENTAL_GS VK_DRIVER_FILES=$O/mali_icd.json \
      VK_LOADER_LAYERS_DISABLE='~all~' MALI_BACKEND=fake MALI_FAKE_GPU=$g vulkaninfo --json=0 -o /tmp/vi-$g.json
  python3 -I ../tools/feature-matrix/feature_matrix.py ours --gpu $g --vulkaninfo /tmp/vi-$g.json
done
# 2. matrix + gaps
python3 -I ../tools/feature-matrix/feature_matrix.py gen
```

`extract` needs the primary sources downloaded (R=/tmp/opencode/feature-refs):

```sh
git clone --depth 1 https://github.com/KhronosGroup/Vulkan-Docs.git $R/Vulkan-Docs
git clone --depth 1 https://github.com/KhronosGroup/Vulkan-Profiles.git $R/Vulkan-Profiles
# LunarG desktop baseline 2024 is not committed as a file upstream; build it with Khronos' own tool:
PYTHONPATH=$R/Vulkan-Profiles/scripts:$R/Vulkan-Docs/scripts python3 $R/Vulkan-Profiles/scripts/vkprofiles.py combine \
  --registry $R/Vulkan-Docs/xml/vk.xml --input $R/Vulkan-Profiles/profiles/LunarG/VP_LUNARG_desktop_baseline_2024 \
  --output $R/generated/VP_LUNARG_desktop_baseline_2024.json --profile-name VP_LUNARG_desktop_baseline_2024 \
  --profile-api-version 1.2.204 --profile-version 2 --profile-label "LunarG Vulkan Desktop Baseline 2024 profile" --profile-date 2026-09-16
# ANGLE at Chromium 126 (branch chromium/6478)
for f in vk_renderer.cpp vk_caps_utils.cpp; do curl -sfL \
  "https://chromium.googlesource.com/angle/angle/+/refs/heads/chromium/6478/src/libANGLE/renderer/vulkan/$f?format=TEXT" | base64 -d > $R/angle/$f; done
# Arm blob reports (gpuinfo.org): G610 r54p1 #53324, G615 r44p1 #53727, G925 r49p1 #51936
for id in 53324 53727 51936; do curl -s "https://vulkan.gpuinfo.org/api/v3/getprofile.php?id=$id" -o $R/gpuinfo/profile-$id.json; done
python3 -I tools/feature-matrix/feature_matrix.py extract --registry $R/Vulkan-Docs/xml/vk.xml \
  --profiles $R/Vulkan-Profiles/profiles --desktop-baseline $R/generated/VP_LUNARG_desktop_baseline_2024.json \
  --mesa third_party/mesa --angle $R/angle --steam-caps vk/tests/t_steam_caps.c \
  --gpuinfo v10:53324:$R/gpuinfo/profile-53324.json --gpuinfo v11:53727:$R/gpuinfo/profile-53727.json \
  --gpuinfo v13:51936:$R/gpuinfo/profile-51936.json [--registry-rev ... --profiles-rev ... --mesa-rev ... --angle-rev ...]
```

## Check

`feature_matrix.py check --gpu v11 --vulkaninfo fresh.json` exits 1 and lists every extension, true feature bit and
format feature bit of `data/ours-v11.json` that the fresh capture lacks; new items are reported, not failed. When a
capability is removed on purpose, re-capture (`ours`) and re-run `gen` in the same commit.

## Limits of the extraction (read before trusting a cell)

- PanVK values are its source table evaluated at PAN_ARCH 10/11/13; entries that depend on the kernel (timestamps,
  compressed-format queries, drirc) are shown as `rt`. PanVK runs on panthor, not kbase.
- The profile "formats" and "properties" requirements are compared against what vulkaninfo's profile JSON exports;
  `VkFormatProperties3`-only bits (e.g. STORAGE_READ_WITHOUT_FORMAT) are not in our capture and appear as missing.
- zink's ES 3.x needs are not listed separately in zink.rst; the GL table is the requirement list only (zink exposes
  lower versions with whatever is present).
- The "hw" column is `yes` only when we, PanVK or the Arm blob already expose the item on that GPU; anything else is
  `unknown` unless `data/curated.json` says otherwise with a reason.
